## Review notes

### Security review

Nothing reached the confidence threshold (8 of 10). It looked for network access, telemetry, private interfaces,
new permissions, subprocesses, deserialization and path handling in the range, and scanned every added line for
personal data. Notes below the threshold, and what was done:

- The live suite prints the `cp` command to restore the plist instead of copying it back: left as is, as in the other
  live scripts (macOS rewrites the file while it runs); the labels are removed, which restores the wallpapers. The
  maintainer decided on 2026-10-10 that this is right and updated the project rule to match.
- The live suite prefers an executable `dnm` at the repository root: kept (it is how a copied test kit works).
- `--uninstall-first` could leave the Mac without dnm if the test then failed: fixed (see code review 2).
- Error messages print the user's own words unchanged: not a vulnerability (their own input).
- A leading `-` is unquoted in a suggestion: fixed (see code review 10).

### Code review

1. Live suite used the real store before the private one: fixed (private store first).
2. `cask --uninstall-first` removed dnm before the audit: fixed (after the audit; says how to restore on failure).
3. The live suite does not restore `Index.plist`: decided by the maintainer (2026-10-10): leave it. A restored image is
   equivalent to the original, so `dnm remove` is the restore and `Index.plist` is touched only if necessary; the
   project notes (`CLAUDE.md`) now say so.
4. `set` reported display errors before input errors: fixed (options and label validated before the display is
   resolved or a warning printed).
5. The quoting hint was added when the first word was a display (an alias of an away display): fixed (hint only when
   the word is no display), with a test.
6. `reinstall` hid upgrade failures and checked fewer files: fixed (upgrade only when the version differs, no `|| true`,
   checks `desktop-name` and every completion file).
7. Release docs missed the new stage and option: fixed (header, usage, procedure document).
8. Two inline name comparisons beside the shared matchers: fixed (both use them).
9. The "commands stay thin" test searches text: kept as a tripwire and strengthened: the resolver's matching entry
   points are now internal, so a command cannot call them at all.
10. A leading `-`, `=` or `~` in a quoted suggestion: fixed (`=` and `~` are quoted; dash-leading words use the `=` forms).
11. The contract showed double quotes where the code uses single quotes: fixed (contract updated).

Open questions:

1. A first word that is only part of a display's name (`dnm set in progress` took `in` as part of "Built-in Retina
   Display"): decided by the maintainer (2026-10-10): a name is matched from its beginning, not anywhere inside it
   ("start strict, relax if needed"). Done in `0580876`; `in` now matches nothing on this Mac, and the no-match
   message says how names are matched. Note for later: relaxing to the start of any word would make some unique
   matches ambiguous (for example `HD` among `InSight HD` and `HD Axiom`), which is an error, never a wrong label.
2. An empty first word silently meant the main display: fixed (an empty display is an error).
3. The tap version read from `brew info`: checked against the current output; parsing made robust to a suffix.
4. Display names with quotes or backslashes in the live suite's JSON parsing: accepted for a maintainer-only script.

## Corrections and findings during the release (2026-10-10)

- The first `cask --uninstall-first` failed after the audit passed. Cause: after the code review's advice to uninstall
  only once the audit had passed, the uninstall ran with the temporary test tap already in place, and the unqualified
  `brew uninstall --cask desktop-name-manager` was ambiguous (the cask existed in two taps). The installed dnm was
  untouched, but the cleanup then left the temporary tap behind: it untrusted the tap before untapping, and Homebrew
  refuses to untap a tap it no longer trusts.
- Removing the leftover tap by hand with `brew untap --force` **uninstalled the installed dnm 0.1.2 as a side effect**:
  Homebrew matches an installed cask to a tap by name alone. The planned reinstall restored it. Fixes in
  `scripts/release.sh` (committed after the tag, tooling only): the cleanup untaps first and untrusts after; it
  leaves the temporary tap in place, and says so, when untapping would uninstall an installation the stage was not
  asked to remove; the uninstall names the real tap's cask; installs are detected by the Caskroom, not by name lookup,
  so a leftover tap cannot confuse them. The stage was rerun cleanly (no temporary tap afterwards).
- The upgrade check of spec 005 (User Story 3) was not repeated for 0.2.0: the Mac was reinstalled from nothing after the
  uninstall above, not upgraded from 0.1.2.
