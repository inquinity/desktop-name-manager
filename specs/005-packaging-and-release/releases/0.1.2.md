## Corrections and findings during the release (2026-10-09)

- `brew update` ran a moment before GitHub served the tap's new commit, so the first `brew install` after pushing
  the tap installed the cached 0.1.1 cask. After the tap was fetched, `brew upgrade --cask desktop-name-manager`
  upgraded 0.1.1 to 0.1.2. Wait for the tap push to be visible (or fetch the tap) before the install check.
- The maintainer's `.zshrc` runs `compinit -C`, so the new `_dnm` was not registered until `compinit` was run
  by hand; documented in the README and in spec 007.

## Install checks after publishing

macOS 27.0.1, Apple silicon, 2026-10-09:

- Upgrade (spec 005 User Story 3): `brew upgrade --cask desktop-name-manager` from 0.1.1 to 0.1.2 left `dnm`
  and `desktop-name` reporting `0.1.2 (3)`, linked the three completion files (`_dnm` and `_desktop-name` in
  Homebrew's `share/zsh/site-functions`, `dnm.bash` as `etc/bash_completion.d/dnm`), and `dnm list` still read the
  existing store. The cask test in `release.sh cask` had already shown the files appear after install and
  disappear after uninstall.
- Live Tab (spec 007 quickstart 6), on a pseudo-terminal: in the maintainer's own zsh (after rebuilding the
  completion cache) and in bash 3.2 with the installed bash file, Tab after `dnm ` offered the commands,
  `--style` and `--position` offered their values, `--display` offered `main` and the connected displays,
  and `desktop-name` completed the same way.
- Not run: the withdrawal procedure (spec 005 User Story 6).
