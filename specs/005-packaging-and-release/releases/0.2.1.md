# Release 0.2.1: gate record

Label reuse and `dnm cleanup` (spec 009, feature F4 stage 1): identical labels reuse their image, `dnm cleanup`
replaces `dnm prune`, a reminder when old images pile up, `undo` limited to 60 seconds, and the stored data moved to
format 3. Also the display word and `--display` naming the same display together (spec 008 amendment). Written by
`scripts/release.sh` and the maintainer; committed after publishing (FR-017). Contains no credential, personal
path or identifier.

## Release

- Version: 0.2.1, build 5 (tag `v0.2.1`, commit "Release 0.2.1 build 5")
- Run by: maintainer, with Claude Code
- **A patch release with breaking changes** (maintainer decision, 2026-11-03: keep 0.2.1): `dnm prune` is removed
  (it exits 2 and names `cleanup`), `undo` works for 60 seconds instead of 30 minutes, and the stored data is format
  3, which 0.2.0 refuses ("newer than this tool understands"). The release notes say each plainly.

## Review notes

### Security review

Nothing reached the confidence threshold. No network access, private interfaces or personal data in the range;
deletion is limited to exact `<uuid>.dnm.*` files inside the store; the CodeQL workflow is sound. Notes below the
threshold, and what was done:

- `cleanup` can offer the active label of a display that has been disconnected for 30 days or more: the warning,
  help, contract and README now say a Desktop on a display that is not connected might still show one (`147899a`,
  `f46d9ee`).
- A hand-edited manifest in which two labels share one file could have that file deleted: deferred (the manifest is
  the tool's own file; never produced by `dnm`).
- A temporary tap left behind by `release.sh` blocks the next cask run: deferred (code review finding 6).
- The pinned GitHub Action commits were not checked online against their release tags: left for a later review.

### Code review

1. Asking again for a label that is showing but retired left it retired: fixed (`939188a`; it is active again).
2. Cleanup dated a retired image from its retirement even when seen showing since: fixed (`939188a`; the later of the
   two, spec 009 data model §4, FR-002 and research R5 amended).
3. Undo after a reused `set` retired an image another Desktop still showed: fixed (`939188a`; the change record keeps
   the label's earlier state in an optional `reusedFrom`, and undo puts it back; older records undo as before).
4. README "Full removal" said skipped Desktops keep their picture: fixed (`f46d9ee`).
5. The "no note without a terminal" test never ran `set` or `remove`: fixed (`dd220df`; the decision is a pure
   function, tested, and a test checks that only `set` and `remove` call it).
6. `release.sh` leaves a temporary tap that blocks the next cask run: deferred (maintainer tooling, not shipped).
7. `cleanup --json --yes` said `"deleted": true` when nothing was deleted: fixed (`147899a`).
8. The cleanup question went to standard output while only standard input was checked: fixed (`147899a`; it asks only
   when both are terminals, otherwise it describes).
9. The reminder reads the displays a second time after a command (spec 009 FR-009): deferred (small cost).
10. Spec 001 still mentioned `prune` and the 30-minute undo: fixed (`f46d9ee`).

Open questions, left as they are (maintainer approved the plan, 2026-11-03):

1. "Not seen" is recorded only when a writing command runs, so after 30 days without one every off-screen label is
   offered: cleanup's description already says a Desktop not on screen might still show one, and nothing is deleted
   without agreement.
2. The reminder resets only when cleanup deletes something: intended.
3. `cleanup --yes` from a script also deletes active labels not seen for the period: accepted; `--yes` is the
   explicit agreement.

### Re-review of the fixes

No correctness defects; each new test fails without its fix. Minor findings, fixed in `2c740cd` unless noted:

- `Tests/live/live-label.sh --with-cooldown` still waited 31 minutes for deletions: now waits a minute and checks that
  `undo` has nothing to undo and every image stays.
- The cleanup listing shows a retired image's age from its retirement while selection uses the later sighting: kept
  (it matches spec 009 §4, and the retirement age is the true fact).
- Undo does not restore `supersededBy`: kept (nothing reads it); spec 001's data model now says so.
- Wording in spec 009 research and a README line wrap: fixed.
- Test gaps: undo after a reuse that replaced a label, and a record without `reusedFrom`, now tested; the empty-delete
  message and the standard-output terminal rule are not (hard to reach from the command tests).
